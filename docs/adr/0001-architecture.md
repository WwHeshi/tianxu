# ADR 0001：前后端分离与确定性排盘边界

- 状态：已接受
- 日期：2026-07-22
- 决策范围：MVP 的本地开发和第一版部署

## 背景

八字分析同时包含两类性质不同的工作：一类是受历法、时区和流派规则约束的计算；另一类是面向用户的自然语言解释。出生时间和地点属于敏感个人信息，结果还需要能够复核和重现。因此不能把四柱计算交给每次可能产生不同结果的大模型。

## 决策

### 1. Next.js + TypeScript 前端

使用 Next.js 承载响应式表单、命盘展示和对话界面，浏览器通过 REST 调用资源接口，并为长文本分析和聊天保留 SSE 流式通道。前端不复制排盘算法，所有命盘字段以 API 返回值为准。

### 2. FastAPI + Python 后端

FastAPI 负责输入校验、API 契约、排盘调用、Agent 编排和持久化。Pydantic 模型作为前后端之间的边界；后端可通过 OpenAPI 生成前端类型。

### 3. 确定性排盘引擎与 Agent 分离

排盘引擎接收标准化出生信息和显式 `calculation_policy`，输出版本化的命盘 JSON。第三方历法库只能在引擎适配层使用，并通过 golden tests 校验边界行为（节气、换日、时区等）。

Agent 只读取排盘输出、规则库上下文和用户问题。它可以组织和解释结果，但不得重算、改写或补造四柱；结构化报告需经过 schema 校验。模型、提示词和规则库版本写入分析元数据，以支持回归测试。

### 4. PostgreSQL 持久化

MVP 使用 PostgreSQL 保存出生资料（按隐私策略）、命盘快照、分析报告和会话消息。每个命盘快照记录 `engine_version` 与 `policy_version`，避免引擎升级后旧报告失去可解释性。开发环境由 Docker Compose 提供数据库。

### 5. REST + SSE，而非多智能体

命盘、分析和会话资源采用版本化 REST 路径；分析生成和追问接口预留 SSE，便于逐步显示模型结果、处理中断和重试。MVP 使用一个 Agent 编排器和 Provider Adapter，不引入多智能体、队列或 Redis，直到出现明确的并发和长任务需求。

## 数据流

```text
出生信息
  -> FastAPI 输入校验与标准化
  -> 确定性排盘引擎（命盘 JSON + 规则/引擎版本）
  -> 持久化命盘快照
  -> Agent 编排器（命盘 + 规则 + 问题）
  -> 结构化报告 / SSE 事件
  -> Next.js 展示
```

## 影响与约束

- 相同输入、相同策略和相同引擎版本必须得到相同命盘；golden tests 是发布门槛。
- 规则差异（例如立春分年、节气分月、子时换日、真太阳时）必须显式配置并展示给用户。
- 日志、错误追踪和模型请求只保留完成任务所需的最小数据，默认脱敏出生信息。
- Compose 中的默认凭据只用于开发；生产环境必须通过秘密管理和 TLS 配置覆盖。
- SSE 客户端需要处理断线、取消、超时和结构化输出校验失败。

## 未决事项

登录与跨设备历史记录、具体模型供应商、大运/流年范围和多流派支持在产品决策确认后单独记录 ADR，不在本决策中预先锁定。
